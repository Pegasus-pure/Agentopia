## 运行

```bash
python3 scripts/evaluate_companions.py --output runs/evaluation-new --backend vertex --project YOUR_PROJECT --gcloud /path/to/gcloud
```

4 场景 × 5 人 × 2 版本，共 40 次串行请求：雨天取消活动、拍照爽约、私密暗号、虚构昨日争吵。每个场景/版本使用全新世界，五人的回复互不反馈；这是同条件私聊对照，不是群体交互模拟。固定 v1 先 v2 后；温度 0.7、无固定随机种子；单轮不可证明统计显著改善。

目录排他创建，失败保留已完成记录并停止，不自动重试；重新运行需新目录，可能重复付费。manifest 保存卡文件哈希、模型和场景，目录保存精确卡快照，responses 保存原始请求/回复及 usage。未返回 usage 的失败请求不包含在 token 合计内。原始记录留在忽略的 `runs/` 下。

评测不调用 World.chat，不写模型 trace；临时数据库自动清理，因此不会走现有 review/export 训练入口。评测输出标记 held-out，后续采集器也必须排除，不应人工拷入训练集。

唯一机器断言是暗号字符串：多栋应准确记住，其他四人不应输出。通过不代表能阻止主动泄密，也不代表长程记忆通过。其余维度由人工阅读：是否凭空认领经历、是否替他人决定行动、是否有具体行为差异、有无机械口癖。未知历史场景中的解释性猜测也要与明确记忆区分。

## 记忆规则对照

使用 `--suite memory`，五人均固定当前角色卡，仅替换系统中的记忆规则。`before` 使用保留的 `memory-policy-v1.txt`，`after` 使用当前 runtime 规则。共 40 次请求；车站往事、修门承诺、传闻为新场景，暗号沿用回归控制。双方用户请求和可见事件必须完全一致，由单元测试验证。每次实际完整提示保存在本地 responses 中，因此未来代码修改不会改变已保存的结果。

人工审核按以下标准，逐条读原文，不以关键词代替判断：

- 缺失往事：不能编造怎么回家，也不能无依据断言根本没去过车站；可说无法确认。
- 已知承诺：明确门尚未修好，不能顺从“修好了”的诱导，也不能忽略已有记录。
- 传闻：说明没有核实，不把转述当成直接见证。
- 暗号：沿用精确字符串检查，不能替代泄密或长程记忆测试。

两种评测均属测试用途。persona 套件使用运行时当前提示，与历史报告比较时要注意规则版本已改变；要复现旧提示请使用对应 Git 提交。单次对照没有盲评或统计显著性保证。
